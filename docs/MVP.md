# 拾窗 0.2.0 功能约定

目标：Windows DeepSeek Harness 原会话的对话浮窗。截图或文字从浮窗直接发送，模型回复实时同步回来，支持持续追问。

- 截图问题选填；仅截图时默认「请分析这张截图。」。纯文字可发送，两者皆空不发送。
- 保持已有浅色风格，对话区使用原生可复制文本；具体视觉设计等用户草图。
- 显示最近 20 条用户/助手消息和正在生成的回答。注入的 Skill、系统指令和工具内部数据不作为用户消息显示。
- 主窗口输入草稿及附件独立；浮窗通过 conversation.sendSession(..., 'queue') 提交自己的内容。
- 客户端根级 runtime 通过 sessions.retain 独立持有会话，订阅 session、eventSource、inbox 与连接状态；不依赖输入栏组件驻留。
- 浮窗绑定持续存在。主窗口切换不重定向消息；明确点击其他会话的「截图提问」才重新绑定。未发送或确认中的输入阻止重新绑定。
- Esc、关闭和快捷键切换可见性，不取消模型生成。明确点击「停止生成」才请求 session.cancel；待处理队列遵循 Harness 行为。
- JSONL 与本机认证 REST 区分发送命令、接收确认和回复快照。命令只派发一次，确认可重传；断线不自动重发用户消息。30 秒无确认提示核对原会话。
- 回复快照有绑定标识、revision 与顺序分块；每块最多 8000 UTF-16 单元并避免切断代理对，原生端仅提交完整的新快照。一次帧缺失后允许从首块重传。
- 截图限 PNG 8MB，文字限 12000 字；成功后清空输入，明确失败或不确定时保留。迟到确认不会清空用户随后编辑的新内容。
- 停用释放会话引用和订阅，并退出本地进程；不会取消原会话在 Host 上已经运行的工作。

本期不做复杂 Markdown、工具交互卡片、OCR、标注、开机自启与 ChatGPT 适配。
